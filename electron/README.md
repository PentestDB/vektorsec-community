1.5) Stage Dependencies for the Installer (stage:deps)npm run package:win* and npm run dist will automatically run npm run stage:deps beforehand.
(scripts/stage-deps.mjs → pnpm install --prod --frozen-lockfile --node-linker=hoisted into .stage\backend and .stage\frontend). Reasons:Normally, pnpm stores node_modules/<pkg> as absolute path junctions tied to the build machine (D:\Project\vektorsec\backend\node_modules\.pnpm\...). When electron-builder copies these reparse points verbatim, the installed app on client machines fails to resolve any modules (MODULE_NOT_FOUND everywhere). Relative junctions do not work either because Windows resolves junction targets relative to the process CWD, not the linked folder.--node-linker=hoisted generates a real folder structure (zero links), and --prod strips out typescript, eslint, and tsx — drastically reducing the installer size.--prefer-offline leverages the local pnpm store so building doesn't require downloading from the internet again.Requires pnpm installed locally (currently using pnpm 11). If you need to stage manually without packaging:npm run stage:depsInstaller size after utilizing stage deps is approximately 330 MB (Electron runtime ~250 MB + production dependencies for backend/frontend). If you change dependency versions, always run npm run stage:deps again (or delete .stage\ folder) before packaging; package:win* automates this.electron/after-pack.js will fail the build if it encounters any symlinks/junctions inside resources\app\{backend,frontend}\node_modules or if any module resolves outside the package (preventing regression issues silently).2) Run Immediately Without Installing (Portable)Bashnpm run package:win

For dynamic configurations (SSH, Telegram, OAuth, SSRF, etc.), place them in %APPDATA%\VektorSec\data\.env, which is the actual file used by the backend (DATA_DIR specified by electron/backend-runner.js), or export them as environment variables.config.toml does not need to be manually prepared — electron/backend-runner.js automatically writes it to %APPDATA%\VektorSec\data\config.toml upon the first launch (generating a random 64-hex SESS_SECRET, pointing mongo_uri/redis_url to 127.0.0.1, and setting [admin] email = "admin@vektorsec.local"), passing this path to the backend via the DATA_DIR environment variable. This avoids writing to Program Files, which is read-only for standard users.Resolution order for config.toml (backend/src/utils/loadConfig.ts):$DATA_DIR/config.toml → <install>\resources\app\backend\config.toml → <install>\resources\app\config.tomlMongoDB + Redis must be available for the backend — Docker is not required; install the portable runtime once using:PowerShellpowershell -ExecutionPolicy Bypass -File scripts\local-db.ps1 install
This script downloads MongoDB 7.0.45 (mongod) + Redis 5.0.14.1 (Windows) into %APPDATA%\VektorSec\runtime (~130 MB post-extraction) and starts them up immediately. Afterwards, electron/local-db.js will automatically start both services every time the app opens (skipped if ports 27017/6379 are already in use or if VEKTORSEC_LOCAL_DB=0 is set). If both are missing, the backend throws Secret MONGO_URI not found / REDIS_URL not found and retries every 5 seconds → the web page opens at :3001, but login results in a Gateway upstream error.7) Initial Admin Account (Logging into the Admin Panel)This application has no hardcoded admin password (by design — to prevent embedded secrets in distributed binaries).     --type 1y --hwid HWID-XXXX-XXXX-XXXX-XXXX

# Specify custom expiration date: --expires 2026-12-31
Ray places the public key at electron/license-public-key.pem (gitignored) and builds the .exe — the client does not receive the private key, preventing them from minting their own keys.Client pastes the license key into the app → Backend validates the signature + HWID + expiration date via fail-closed logic: incorrect/expired/wrong machine key → Scope Guard immediately locks down.If no key is entered → 30-day Trial automatically initiates on the new machine (HWID).Anti-TamperSecrets (public key + HWID collation logic) are separated into a native addon backend/native/ (C++/N-API) with a JS fallback for dev/test via backend/src/utils/drm/nativeBinding.ts.The actual license validator (backend/src/utils/drm/license.ts) uses Ed25519 asymmetric cryptography — clients possess only the public key.Re-verifiable at backend/src/utils/drm/ + backend/tests/license.test.ts.Limitations (Prerequisites)The backend still requires MongoDB + Redis as external dependencies (the app will launch them without Docker, but DB/Redis must be installed or their URLs pointed via environment variables) — whereas the DRM license is self-contained and does not rely on external services.
